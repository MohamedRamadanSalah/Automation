# Agent I/O Contracts

Seven agent roles, all calling **OpenRouter** through the OpenAI-compatible SDK using one shared default model (per-role override via `agent_configs`, FR-022). Every agent returns a **validated Pydantic-shaped JSON object**; malformed/incomplete output is retried up to `AGENT_MAX_RETRIES` then the step is flagged (FR-017a, SC-012). Each agent runs in JSON mode with a strict system prompt; temperature defaults low for accuracy.

Common envelope every agent response is validated against:

```jsonc
{
  "ok": true,                 // false ⇒ agent self-reports it could not complete
  "data": { /* role-specific, schemas below */ },
  "notes": "string (optional)"
}
```

Concurrency: per-tool agents (Research→Ranking) run under an `asyncio.Semaphore(AGENT_CONCURRENCY)`. A failure for one tool is isolated and recorded as an `analysis_gap`; other tools continue (FR-011).

---

## 1. Research Agent
**Purpose**: Collect & summarize what the tool is (FR-007).
**Input**:
```json
{ "tool": { "canonical_name": "string", "url": "string", "source_refs": [], "raw_signals": {} },
  "collected_text": "string (extracted article/readme text)" }
```
**Output `data`**:
```json
{ "summary": "string (<= 200 words)",
  "category": "string",
  "key_features": ["string"],
  "primary_use_cases": ["string"] }
```

## 2. Trend Analysis Agent
**Purpose**: Explain *why* it is trending now (FR-007).
**Input**: research output + `raw_signals` (stars/upvotes/velocity) + `discovered_at` window.
**Output `data`**:
```json
{ "trend_rationale": "string",
  "drivers": ["string"],
  "momentum_assessment": "low|moderate|high",
  "evidence": ["string"] }
```

## 3. Technical Analyst Agent
**Purpose**: Evaluate strengths & weaknesses (FR-007).
**Output `data`**:
```json
{ "strengths": ["string"],
  "weaknesses": ["string"],
  "maturity": "experimental|emerging|established",
  "technical_merit_0_100": 0 }
```

## 4. Comparison Agent
**Purpose**: Compare against competitors (FR-007).
**Output `data`**:
```json
{ "competitors": [ { "name": "string", "how_it_compares": "string" } ],
  "differentiation": "string",
  "positioning": "leader|challenger|niche|new-entrant" }
```

## 5. Ranking Agent
**Purpose**: Produce the per-dimension inputs for the **versioned weighted composite** (FR-008, R8). The agent supplies normalized 0–100 dimension values + justification; the *final composite* is computed deterministically in code from `scoring_methods.weights` (not by the LLM) for reproducibility.
**Input**: outputs of agents 1–4 + raw popularity/source signals.
**Output `data`**:
```json
{ "popularity_0_100": 0,
  "momentum_0_100": 0,
  "technical_merit_0_100": 0,
  "source_credibility_0_100": 0,
  "justification": "string" }
```
**Code-side**: `score = Σ(weightᵢ × dimensionᵢ)`; persisted to `tool_profiles.score` + `score_components`.

## 6. Report Writer Agent
**Purpose**: Produce professional report sections in Markdown (FR-012, FR-013). Invoked once with the ranked tool set.
**Input**: ordered list of tool profiles + ranking + run metadata.
**Output `data`**:
```json
{ "title": "string",
  "executive_summary": "markdown",
  "trend_analysis": "markdown",
  "tool_profiles_md": "markdown (one block per tool, in rank order)",
  "recommendations": "markdown",
  "conclusions": "markdown" }
```
Cover page + table of contents are generated by the **template/PDF layer** (CSS paged media), not the LLM. Section order assembled by code = cover, executive summary, TOC, trend analysis, tool profiles, rankings, recommendations, conclusions (FR-013).

## 7. Quality Reviewer Agent
**Purpose**: Review the assembled draft; drive the **bounded revise→re-review loop** (FR-010).
**Input**: full assembled Markdown draft.
**Output `data`**:
```json
{ "passed": true,
  "score_0_100": 0,
  "issues": [ { "section": "string", "severity": "low|medium|high", "fix_suggestion": "string" } ] }
```
**Loop**: if `passed=false` (or `score` below `REVIEW_PASS_THRESHOLD`), feed `issues` back to the Report Writer for a revision, re-review — repeat up to `REVIEW_MAX_ATTEMPTS`. After the cap, finalize and store any unresolved `issues` in `reports.review_notes` (FR-010).

---

## Error & retry semantics (all agents)
- Transient provider/network errors → tenacity retry with backoff, bounded by `AGENT_MAX_RETRIES` (FR-025).
- Schema-invalid output → one corrective re-prompt ("return valid JSON matching schema X"), then count as failure for that step.
- A failed per-tool agent → record `analysis_gaps` entry on the profile; do not abort the run (FR-011).
- All provider error details are **redacted of secrets** before logging/persistence (FR-027).
